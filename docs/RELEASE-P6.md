**Half-A/Labs package / Document Foundry 0.7.0.** Northstar B8 interface remains 03. The underlying
reference platform remains the v0.3.0 chassis-03 implementation. This record is owner-only and does
not appear in supplier PDFs.

## Deliverables

Seven separate component masters and seven separate field copies: B8 32 pages; mux 3; LCD 5; motor
4; temperature sensor 3; button assembly 3; oscillator 2. Correspondence is a separate 10-page
source/field pair. **52 component pages; 62 pages with correspondence.** The optional recipient
folder has seven files by retaining the motor/sensor bundle. This does not merge their canonical
source papers or supplier identities.

The complete archive stores each clean and field source once, with its manifest; combined binders
and grouped handouts are regenerated by `tools/assemble_existing.py` without LaTeX or re-corruption.
`tools/project.py docs` performs the full authoring/build pipeline. No font files, compiler outputs,
dependency caches or previously-versioned nested ZIPs are included.

## Manual content checks

The detailed B8 reference has 32 bookmarked sections and a complete 62-register address/access/reset
catalogue checked against the interface-03 source snapshot. It explains field masks, latched high
bytes, staged writes, ownership, interrupt entry/return/W1C, clock selection/PLL/key failures, ADC
timing and freshness, PWM phase/shadow endpoints, WDT/DMT key windows, reset causes/retention and
the native C++ binding. Generic peripheral examples do not choose the application's PLL plan or
implement the blender state machine.

The controlled preexisting source snapshots remain unchanged. A separate B8 register JSON snapshot
was added and hash-locked for the expanded reference. Declared lexical ownership checks passed. They
are useful regression guards, not semantic proof; publication was also reviewed against the actual
model sources.

## Visual review

All 62 clean and 62 encoded field pages were rendered with PDFium. The 32-page B8 clean and field
reference and all other source/field papers were reviewed in page-labeled contact sheets, with
full-size examination of register/detail text and the new wear placement. Clean builds have no
overfull TeX boxes. Review checked tables, diagrams, page numbers, letters, low/high pair notation,
arithmetic symbols, clipping and excessive wear over content. The oscillator replay uses the same
encoded output.

Wear is intentionally uneven: coffee on motor page 1, buttons page 2, and correspondence pages 3 and
7 only. All other pages have non-coffee histories. Each supplier has a different copier identity and
intensity profile. This is not calibrated against physical copiers; OCR resistance is not asserted.
Protection applies before final JPEG encoding, so encoded-page visual review remains necessary.

## Runtime changes and limits

The platform-diff record confirms that none of `sim/src/` or the component model headers changed. P6
corrects SDK/firmware comments, adds documentation-example tests and their build target, and adds
owner-readiness notices. Existing hardware behavior is not secretly advanced to chassis 04 by the
new manual.

**Jar interlock remains specified, not implemented.** S2, PB3/PB4 and U_IL behavior exists in the
current correspondence/r4 drawing and proposed case record, but not in the bundled chassis-03 board.
A hardware adapter, physical board, general scenario player, graphical front panel and CPU
instruction-set interpreter are not delivered. The native runtime is cooperative: a host callback
that never returns or accesses the SDK can block logical time. A host timeout is not an emulated
watchdog reset.

The firmware starter is intentionally unfinished and drive-off. Historical platform acceptance
scenarios include retired algorithm choices; they are not a hidden current rubric for New Employee.
Current accepted behavior comes from the correspondence, with hardware contracts in the supplier
manuals. No physical safety certification, braking, guard locking, motor fuse sizing or single-fault
tolerance is established by these files.

## Reproduction commands

```sh
python tools/project.py doctor
python tools/project.py test
python tools/project.py docs
python tools/project.py bundle --output ../Half-A/Labs-Blender8-Complete-v0.7.0.zip
```

For the separate tested Clang configuration, choose a fresh CMake build directory and
`-DCMAKE_CXX_COMPILER=clang++`. Do not change compilers inside an existing CMake cache. Full
rendering needs TeX and the pinned Python dependencies; assembling existing included PDFs and
running native C++ do not require TeX.
